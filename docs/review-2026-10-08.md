# School Admin review — 8 October 2026

This review uses the published application at `8b55713` as its baseline. It covers the integrated student/staff administration, academic configuration, authentication, notices, leave, certificate registry, IPFS and deployment tooling. Go exercises and student PDF report export remain outside the agreed scope.

## Changes

### Permissions and account sessions

- Staff-edit permission no longer permits creating arbitrary role accounts, granting administrator privileges, taking over an administrator account or changing a login email. Administrator-only actions are enforced by the API; matching controls and direct page access are restricted in the frontend, while ordinary staff profile editing remains available.
- Disabling a user or role revokes refresh sessions. Login, password and status changes lock user records consistently, and each JWT receives a unique identifier.
- Frontend requests and refreshes belong to one login session. Switching accounts aborts old requests, clears cached data and prevents late responses from modifying a newer session.
- Other browser tabs receive a non-secret session-change notification and stop displaying the old identity. Persisted identity is now per-tab; old shared login storage is removed. Existing browser sessions must log in again after this upgrade.

### Database and product consistency

- Section renames/deletions update class membership and teacher/student relationships. Legacy numeric section identifiers are normalized before a numeric name could change their meaning.
- Class renames update notice recipients. Deleting a class clears its dependent section assignments. Removing an occupied section returns a conflict instead of silently corrupting relationships.
- Related administrative writes use a consistent advisory-lock order to avoid cross-user and academic-record deadlocks.
- Dashboard leave totals belong to the current user and count full calendar date spans, including spans longer than one month. Deleted notices are filtered before limiting the result set. Parent counts no longer assume that custom role ID 4 means parent.
- Malformed or oversized JSON returns a client error. Invalid academic identifiers and leave-policy inputs are rejected deliberately.

### Frontend behavior

- Empty query lists retain cache tags, so creating the first item refreshes the page data. Related student, staff, class and notice caches are invalidated after relevant changes.
- Missing student/staff records display an error instead of an editable empty form.
- Administrators delete notices directly; other authors request deletion according to their permissions.
- Leave forms reject missing/invalid dates, display server errors and retain inputs after failure.
- Routes load lazily. The main generated JavaScript chunk changed from approximately 1.55 MB to 489.60 kB (162.70 kB gzip in the local build). This is a bundle measurement, not a claim about measured user latency.
- Mobile navigation and long verification identifiers fit smaller screens.

### Chain and operations

- Standalone contract deployment refuses to overwrite existing deployment metadata.
- Backups use one deployment lock across all destinations and record the actual immutable image IDs used by running containers. A backup is reported complete only after services restart successfully.
- A dedicated recovery rehearsal restores PostgreSQL, chain history, deployment metadata and IPFS into new isolated volumes, then checks the same student, certificate, metadata CID, registry and revocation flow.
- GitHub Actions builds and tests a fresh isolated stack. It does not deploy the website automatically.

## Remaining boundaries

- This is an interview demonstration with a private test chain, locally stored IPFS content and a shared administrator login. It is not a production school service or an independently isolated sandbox per visitor.
- Live email delivery requires a configured provider; the demonstration does not establish email delivery without those credentials.
- Frontend production dependency audit reports no known advisories at review time. The development toolchain still contains an unpatched `braces` advisory: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). It is not bundled into the served frontend.
- The chain production lockfile audit reports one low-severity unpatched elliptic advisory. The complete development graph still reports 30 advisories (11 high, 12 moderate, 7 low); the Hardhat/compiler/test packages are excluded from the chain runtime image. Bundled Ganache crypto packages are separately hardened and checked. See [blockchain audit details](../blockchain/README.md).
- Dependency audit results are time-sensitive and do not prove the absence of vulnerabilities. A lockfile audit alone misses dependencies bundled inside Ganache.
- The backup is sensitive: it includes private chain keys and server configuration. Keep it off GitHub and restrict access. Automated restore testing does not substitute for retaining a real server backup.
